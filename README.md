# 弹球

一个纯 pygame 的弹球游戏。球在竖屏里斜向弹跳，砸横杠，横杠上的数字就是它的血量，
打完掉到下一层，一路掉出屏幕底部就算通关。

## 跑起来

```bash
.venv\Scripts\python.exe main.py            # 用同目录的 game.toml
.venv\Scripts\python.exe main.py 别的.toml  # 指定配置文件
```

按键：`R` 重开，`ESC` 退出。

## 窗口缩放

窗口默认**可以拖大拖小**（想固定就写 `resizable = false`）。拖动之后：

- 各屏宽度**平均分**，中间的竖线保持原宽
- 横杠重新铺到各自的行上 —— 按**行号**定位，所以上面几根已经被打掉了，下面的也不会串位
- 球**按比例挪过去**，缩得太小会被按回面板里
- **物理效果跟着缩放**（见下）

窗口压得很扁时，顶部信息区最多占屏高的 `header_ratio`（默认 0.35），给横杠留地方；
球名和伤害谁太长谁缩字号，再塞不下就截断加省略号，不会越出面板。

### 物理随窗口缩放

```toml
[global]
scale_physics = true     # 默认开
```

开着的时候，每个屏算一对缩放系数：

| 系数 | 取法 | 乘在什么上 |
| --- | --- | --- |
| `scale_y` | 面板高 ÷ `panel_height` | 重力、反弹力度 |
| `scale_x` | 面板宽 ÷ `panel_width` | 横向速度 `speed_x` |

**为什么要乘重力**：落体时间 `t = √(2d/g)`。面板变高时 `d` 变大，如果 `g` 不变就会
落得更久、弹跳高度在视觉上占比变小。让 `g` 和 `d` 同比例放大，两者正好抵消 ——

- **弹跳高度占层间距的比例不变**（实测 0.80~0.91，随窗口尺寸基本恒定）
- **球从顶落到底的耗时不变**（实测 0.89~0.94 秒，任何窗口尺寸都一样）

球的**半径、横杠厚度、字体不缩放** —— 只是物理量跟着窗口走。
想要老行为（窗口变大球就显得弹得矮）就写 `scale_physics = false`。

## 单球 / 双球

**写几个 `[[panel]]` 就有几屏**：1 个 = 单屏，2 个 = 左右分屏比谁先到底。

### 临时切成单屏（不动配置文件）

有时候就想看某一颗球自己玩 —— 在**选球界面按 `S`**（或点左下角「只看这屏」），
就只留当前聚焦的那一列，窗口也会跟着缩成单屏的宽度。再按一次 `S` 恢复双屏。

这个开关只在本次运行有效，不改配置文件。

### 永久切成单屏

在不想玩的那一屏里加一行：

```toml
[[panel]]
enabled = false        # 关掉这一屏
bars = [10, 10, 10, 10]
...
```

（或者把整段 `[[panel]]` + `[panel.ball]` 删掉/注释掉。全关完会报错，至少要留一屏。）

### 横杠数量与对齐

每个屏幕的横杠数量由 `[global]` 里**一个共用的数**决定，所以左右永远对得齐：

```toml
[global]
bar_count      = 5     # 每一屏几根横杠（左右共用，保证行位置一致）
default_bar_hp = 1     # 哪一屏 bars 写少了，在底部补这个血量的横杠
```

两屏的 `bars` 都写满 `bar_count` 个值就最直观；写少了会在底部自动补
（控制台会提示补了几根、补成多少），写多了会直接报错让你把 `bar_count` 调大。

`bars` 从**上面第一行往下排**，所以第 i 个值在两屏都落在同一个高度。

任意一屏打完就**整个游戏暂停**，屏幕中间显示谁获胜，按 `R` 重开。

## 球库与选球界面

**球库**是一个单独的文件（默认 `balls.toml`，和关卡配置同目录），所有能选的球都写在那：

```toml
[[ball]]
name         = "对数球"
desc         = "每次撞击，把横杠的数字取常用对数。1E10000 → 10000。"
base_damage  = 1
bounce_speed = 620
speed_x      = 220
color        = [60, 120, 220]
on_hit = [{ op = "target_log" }]
```

关卡配置里用 `balls_file` 指到它：

```toml
[global]
balls_file = "balls.toml"
```

然后每一屏用哪个球，有**三种写法**：

| 写法 | 效果 |
| --- | --- |
| 什么都不写 | 开局弹**选球界面**，从球库里挑 |
| `ball = "对数球"` | 写死用球库里的这颗，这一屏不参与选择 |
| `[panel.ball]` 内联 | 就地把球写在面板里，也不参与选择（老写法，仍然兼容） |

只要**有任何一屏没写死球**，开局就会先弹选球界面。左右两屏各一列、同屏一起选：

```
鼠标         悬停高亮，点一下选中，点左下角「编辑横杠」进编辑器
↑ / ↓        在当前的列里上下移
Tab / ← / →  在左右两列之间切换
Enter / 空格  开始游戏
E            进横杠编辑器
Esc          退出
```

列表里**每一行就是一根"横杠"**：选中的那根"上墨"变成实心黑，没选中的是空槽。
当前操作的那一列，标题是红的、底下一条红线；另一列里的选中项画成空心，一眼看出焦点在哪。

写死了球的那一列会锁住、不参与选择，Tab 直接跳过它。
按 `R` 重开会**回到选球界面**，可以换个球再来。

球库文件不存在也不报错，只是球库为空 —— 这时如果还有屏需要选球，才会提示你去写 `[[ball]]`。

## 横杠编辑器

选球界面左下角点「编辑横杠」（或按 `E`）进去，**可视化地安排左右两屏的横杠**：

```
鼠标          点一行选中它开始输入；点「加一根 / 删一根」调条数
↑ / ↓         在当前列里换行
Tab / ← / →   在左右两屏之间切换
数字键 . E     输入数字，支持科学计数法（1E10000 这种）
Backspace     删一个字符
Enter         确认这一行
Esc           取消当前输入；不在输入时返回选球界面
```

- 每一行画成**游戏里真正的横杠**（黑底白字），所见即所得
- 点开一行直接打字，**第一个按键会把旧值整个替换掉**，不用先删干净
- 输入的东西解析不了（比如手滑打成 `abc`）就保留原值，不会把横杠弄没
- 输入 `1.6e9` 这种会自动归一化成规范的显示形式（`1600000000`）

**条数是左右共用的**（这样两屏的行位置才对得齐），所以「加一根 / 删一根」是两边一起变；
**数字是左右分别定义的**，可以一边一个样。

⚠️ 改完的内容**只对本次运行有效**，不会写回 `game.toml`。想永久保存就手动抄回去。

## 玩法

- 球有 `(x, y, vx, vy)`，受重力作用。撞到横杠上表面就**反弹**（给一个固定的向上初速度），
  撞到左右两侧屏幕壁就**换向**，然后重新落下再撞，反复砸同一根横杠。
- **开局球是竖直往下掉的**（横向速度 0），到**第一次弹跳**时才随机决定往左还是往右 ——
  两颗球各掷各的硬币，所以不会总是往同一边跑。之后横向速度就固定了，只有撞墙才换向。
- 每次撞击结算一次当前伤害，然后触发这个球的 `on_hit` 能力（可能改伤害、改重力、改横杠血量……）。
- 横杠血量 `<= 0` 就消失，球自然落到下一根。
- 球掉出面板底部 = 这一屏通关。两屏就是谁先到底谁赢，**一屏打完立刻全场暂停**。

球的弹起高度由 `反弹力度` 和 `重力` 决定：

```
弹起高度 = bounce_speed² / (2 × gravity)
```

## 配置文件

`game.toml`。写几个 `[[panel]]` 就有几屏（1 个单屏，2 个左右分屏）。

数字可以写整数、浮点或字符串；**超过 float 范围（约 1.8E308）的必须写成字符串**：

```toml
bars = [9727, 1600000000, "1E12", "1E120", "1E888"]
```

每个球的字段：

| 字段 | 说明 |
| --- | --- |
| `name` / `desc` | 显示在面板左上角的名字和描述 |
| `base_damage` | 初始伤害，支持 `"1E100"` 这种大数 |
| `bounce_speed` | 反弹力度（像素/秒） |
| `speed_x` | 横向速度的大小；方向在第一次弹跳时随机（左/右）。`0` = 只上下弹 |
| `start_x` | 出生点横向位置，`0`=最左 `1`=最右 |
| `radius` / `color` | 半径和颜色，`radius` 不写就用全局的 |
| `on_hit` | 撞击后触发的能力列表 |

## 能力算子（on_hit）

`on_hit = [{ op = "算子名", 参数 = 值 }]`，按顺序执行。内置的算子都在 `effects.py`：

**改球**

| 算子 | 作用 |
| --- | --- |
| `add_damage` | 攻击力 `+value`（默认 1） |
| `mul_damage` | 攻击力 `×value`（默认 2） |
| `set_damage` | 攻击力直接设成 `value` |
| `scale_bounce` / `set_bounce` | 反弹力度乘 / 设 |
| `set_gravity_mult` / `scale_gravity_mult` | 重力倍率设 / 乘（`0` 就是失重） |

**改横杠**

| 算子 | 作用 |
| --- | --- |
| `target_log` | 把横杠数字取常用对数（对数球）：`1E10000 → 10000` |
| `target_scale` / `target_add` / `target_set` | 横杠血量乘 / 加 / 设 |
| `annihilate` | 直接湮灭（反物质球） |

几个现成的例子（`game.toml` 末尾有注释掉的整段配置，打开就能玩）：

```toml
# 对数球
on_hit = [{ op = "target_log" }]

# 反物质球
on_hit = [{ op = "annihilate" }]

# 虚空球：没有重力，一直往上飘
on_hit = [{ op = "set_gravity_mult", value = 0.0 },
          { op = "add_damage", value = 1 }]
```

## 写自己的算子

在 `custom_effects.py` 里注册，游戏启动时会自动加载：

```python
from effects import register

@register("横杠砍半")
def halve(ctx, times=1, **kw):
    for _ in range(int(times)):
        if ctx.bar.hp <= 1:
            break
        ctx.bar.hp = (ctx.bar.hp / 2).to_integral_value(rounding=decimal.ROUND_CEILING)
```

`ctx` 上能拿到 / 改的东西：

- `ctx.ball.damage` — 当前伤害（`Decimal`，用 `bignum.parse(...)` 转）
- `ctx.ball.bounce` — 反弹力度
- `ctx.ball.gravity_mult` — 重力倍率
- `ctx.ball.vx` — 横向速度
- `ctx.bar.hp` — 被打的那根横杠的血量（`Decimal`）
- `ctx.panel` — 整个面板，可以增删横杠、直接改球的位置等

`custom_effects.py` 里已经内置了 `halve_target`（砍半）、`hasten`（越撞越快）、
`parity_chaos`（奇偶整活）和你自己加的 `翻倍`。

**注册完一颗新球 = 在 `balls.toml` 里复制一段 `[[ball]]` 改改**，选球界面里就自动多一个选项。
如果新球的 `on_hit` 里用了自己写的算子，记得先去 `custom_effects.py` 注册那个算子。

## 关于数字

**游戏里出现的数字都是整数。** 但两类数字的取整方向不一样，因为它们的性质不同：

| | 性质 | 取整方向 | 为什么 |
| --- | --- | --- | --- |
| **横杠血量** | 要被打掉的**目标** | `bignum.floor_int()` 向下 | 显示和"死没死"的判定必须一致；而且"削弱"类算子不能反而把数字变大（`target_scale 0.5` 打在 3 上是 1.5，向上取整就成 2 了） |
| **球的伤害** | 一个**增益/速率** | `bignum.ceil_int()` 向上 | 向下取整会把球**归零**（`mul_damage 0.5` 让伤害 1 → 0.5 → 0，球就废了）；向上取整只会"至少不亏" |

所以：

- `target_log` 打在 11 上：`log10(11) = 1.0413...` → **向下** → `1`
- `mul_damage 0.5` 的球：伤害 1 → 0.5 → **向上** → `1`，永远不归零

**显示层不取整。** 取整只在数据产生的地方做（横杠初始化时、每次算子算完之后）。
否则会出现"屏幕显示 0、实际还有 0.0413"这种对不上的情况 ——
一根写着 `0` 却不消失的横杠，看起来就是 bug。

指数 ≥ 0 的数（`1E10000` 这种）本来就是整数，`floor_int` / `ceil_int` 原样返回，
**不会展开成超大整数**，`1E1000000` 取整只要几微秒。

## 关于超大数

数字统一用 `decimal.Decimal`（40 位有效数字，指数范围拉满），所以 `1E10000` 这种不会溢出。
bignum 的显示规则：十进制位数小于 10 就完整写（`1600000000`），否则写科学计数法（`1E10`、`9.999E99`），
阈值可以用 `full_digit_limit` 调。

注意一个必然的结果：**当伤害相对横杠血量太小的时候，减不掉**。
比如 `1E10000 - 1` 还是 `1E10000`（差得太远，40 位精度里看不见）。这不是 bug，
这正是"对数球"存在的意义 —— 先把数字拉下来，再慢慢磨。

## 打包分享给别人

打包配方在 **`ballgame.spec`** 里，一条命令就够：

```bash
pip install pyinstaller
pyinstaller ballgame.spec
```

打出来的东西在 `dist/ballgame/`：

```
dist/ballgame/
  ballgame.exe        ← 双击就能玩
  game.toml           ← 配置就放在 exe 旁边
  balls.toml
  custom_effects.py
  _internal/          ← PyInstaller 的内部文件，别动
```

把这个**文件夹整个压缩**发出去就行。

### 配置是怎么被找到的

**两级查找**（`paths.py`）：

```
先看程序旁边（exe 所在目录 / 开发时是 .py 所在目录）
  ├─ 有 -> 用这份            ← 使用者改了才生效
  └─ 没有 -> 用打包进 exe 的那份（PyInstaller 解压到 _MEIPASS）
```

所以两种玩法都成立：

- **朋友只是玩** —— 双击 exe，用打包进去的默认配置，开箱即用
- **朋友想改** —— 把 `game.toml` / `balls.toml` 放到 exe 旁边，就覆盖掉内置的
  （想改哪个放哪个；两个都想改就两个都放）

同理，**`custom_effects.py` 也优先从 exe 旁边加载**，旁边没有才用打包进 exe 的默认示例 ——
这样别人也能自己写算子（在这个文件里 `@register("名字")`，见上文）。

spec 里 `console=False`，打包后没有控制台，`print` 没人看得见，所以出错时程序会
**弹一个系统对话框**（见 `main.py` 的 `_fatal()`），不会"闪一下就没了"。
